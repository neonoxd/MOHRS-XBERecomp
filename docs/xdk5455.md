# XDK 5455 support

Medal of Honor: Rising Sun links XDK 5455 (XAPILIB, D3D8, DSOUND, XGRAPHC, XBOXKRNL, LIBCMT), a build the SDK did not
know. This records how its symbols were found and what is left.

## Symbols (done for default.xbe and moh3rdc.xbe)

`config/game.toml` names 130 of the 248 functions the runtime knows, plus 11 of 13 data addresses (126 and 10 before
the runtime review added five 4831 names and `D3D_FvfShader`). Every other name is **absent from the image**, not
unidentified:

| Group | Why it is 0 |
|---|---|
| Bink, XNet, XOnline, Winsock (41) | Libraries not linked: the XBE lists no BINK/XNET/XONLINE library and has no such section |
| `CDirectSoundStream_*`, `DirectSoundCreateStream`, the `DSound_StreamVtable`s, and 39 other DSOUND names | Game code calls exactly 20 DSOUND entry points, all named (`re/lib_inventory_default.txt`); MOHRS uses no DirectSound streams, no `DirectSoundDoWork`, no listener setters |
| 13 D3D names (`SetLight`, `SetMaterial`, `DrawVerticesUP`, `SwitchTexture`, ...) | Every D3D function `.text` calls is named except four that need no host replacement (a `jmp` to `Get2DSurfaceDesc`, a surface creator on `XPhysicalAlloc`, a `return 1` stub, a contiguous-memory free) |
| `crt_sin cos tan atan sqrt log log10` | Their bodies all call the CRT helper at `0x1B2308`, whose only callers are `crt_acos` and `crt_asin`: the game uses the inline x87 instructions |

### How

1. `sdk/xdk/5455/signatures.toml` was seeded from 5849: 75 found, mostly by byte hash.
2. `xbe_symbols --candidates` (added) lists for each miss the byte matches with callees ignored and the best
   constant matches. Constant scores were low (0.1 to 0.5): the constants are mostly CDevice offsets, which moved.
3. [XbSymbolDatabase](https://github.com/Cxbx-Reloaded/XbSymbolDatabase) (Cxbx-Reloaded's hand-made XDK
   signatures, built in `re/`, not part of this repo) as an independent oracle: **68 names agree, 0 conflict**, 55
   more filled in. Those carry `# from xbsdb_default.txt` in the config. Name differences are aliased in
   `tools/symbols_compare.py`.
4. `xbe_symbols --check` (added): 82 addresses have the 5849 reference bytes, 40 have other bytes and the same
   convention (stack bytes popped, registers read), none differs. `BeginPush`, `EndPush`, `SetPalette` and
   `IDirectSound_DownloadEffectsImage` have no reference shape and were read by hand.
5. Read by hand (`tools/disasm.py`):
   - `D3DDevice_BeginPush` `0x1C1280`: one stack argument, `jmp BeginStateBig(count + 1)` returning the pointer,
     the contract of the runtime's HLE (XbSymbolDatabase calls it `BeginPush_4`).
   - `D3D_DirtyFlags` `0x1CC428`: `D3DDevice_SelectVertexShader` instruction 11, `or [0x1CC428], 0x70`, the
     instruction the 5849 recipe names.
   - `D3D_IndexData` `0x1CC424`: `D3DDevice_SetIndices` instruction 8 stores `[ib + 4]`, as the runtime does.
   - `0x1D91F8` (`.XTLID` 0x10031), called by the game, is `jmp XInitDevices`.
6. `xbe_symbols --sign config/game.toml` wrote the real `sdk/xdk/5455/signatures.toml`. A clean scan with it
   reproduces the config exactly (255 of 255 entries), and on `moh3rdc.xbe` it finds the same 126 (123 confirmed
   by XbSymbolDatabase, 0 conflicts).

The 5455 signatures only cover what MOHRS links; a later 5455 title can be added with
`xbe_symbols --sign config/game.toml <its config> --out sdk/xdk/5455/signatures.toml`.

## Layout (done)

`sdk/xdk/5455/layout.toml` holds all 43 keys the runtime reads except the two DirectSound stream vtables (MOHRS
links no streams; an unknown key traps where it is first needed). Each value is proven by a `default.xbe`
instruction named in its comment, the same standard as 4831/5849.

- The CDevice moved a lot against 5849 (e.g. Textures `0xB68` vs `0xF88`, RenderTarget `0x15E4` vs `0x1A04`,
  SwapCount `0x2058` vs `0x2478`, Size `0x2080` vs `0x24A0`), but the spacing inside each group is the same:
  SuperSampleX = ZScale + 0x14, BackBufferScale = ZScale + 0x24, ScreenSpaceOffset = Viewport + 0x18,
  Palettes = Textures + 0x10, Depth/BackBuffer/AutoDepth at RenderTarget + 4/0x10/0x1C.
- The miniport sits at device + `0x1808` (5849: `0x1C28`), and its own fields (callback `0x190`, event `0x194`,
  mode `0x1B4`, count `0x1C0`, field `0x1D0`, gamma `0x1DC`/`0x7DC`) are unchanged.
- The D3D globals (`DirtyFlags_Texture`, texture stage stride, stream table), the effects image header and the XPP
  record are unchanged from 5849.
- MOHRS links no display mode getter; the only readers of `DisplayFlags` test bits `0x1000000` and `0x200000`,
  which the runtime's value (`0x400000`, plus `0x10000` for widescreen) leaves clear, as on 5849.
- `D3D_FvfShader = 0x1CEB28` was added to the config's `[data]` (optional in the runtime, Black sets it too): the
  device init `0x1C3D57` stores it as the current vertex shader.

## Runtime review (done)

The runtime was written against 4831 and 5849. Checked against 5455 behaviour, as MOHRS uses it:

- **Calling conventions.** `tools/hle_audit.py` compares every HLE declaration bound by the config (including the
  ones macros such as `COMPLEX_STATE` and `BUFFER` declare) with the stack bytes the 5455 function pops, following
  branches and tail jumps: all match. The guest functions the runtime calls (`D3D_InternalAddRef`/`Release` one
  argument, `D3D_InitDefaultState` none), `XLaunchNewImageA` (pops 8) and the CRT entries (pop nothing) match too.
- **Names the 5849 seed lost.** `D3DDevice_Reset`, `D3DDevice_RunPushBuffer`, `XInputGetCapabilities` and
  `D3D_BlockOnNonSurfaceResource` have runtime HLEs and 4831 signatures but none in 5849's, so the seed dropped
  them. All four are in MOHRS and now in the config and the 5455 signatures (`GetRasterStatus` is absent). Without
  `BlockOnNonSurfaceResource` (`0x1C1850`, called by `D3DVertexBuffer_Lock2` and `D3DPalette_Lock2`) a rewritten
  vertex buffer would never be marked dirty. 5455 `RunPushBuffer` reads data at +4 and size at +0xC as the HLE does.
- **`gpu/state.h` numbering holds.** `SetRenderStateNotInline` splits simple / deferred / complex at 92 and 136;
  all 28 complex `SetRenderState_*` store at `D3D_RenderState + index * 4` with the runtime's index; 23 indices
  XbSymbolDatabase locates agree. Texture stage states: ColorOp 12, BumpEnv 22 to 27, TexCoordIndex 28,
  BorderColor 29, ColorKeyColor 30, as in the enum.
- **Guest structures in `d3d8.cpp`.** Resource headers (Common, Data, Lock, Format, Size) and the surface parent at
  +0x14 (type 0x50000) are the same in 5455's `InternalAddRef`/`InternalRelease`; present parameters and viewports
  are public structs.
- **Vertex shader objects.** 5455's own `CreateVertexShader` lays its object out differently from 5849 (fields at
  +0x1C and +0x114), so `ApplyGuestInputs` (inputs at +0x14) would misread a guest-made object. MOHRS never makes
  one: the game calls only `CreateVertexShader` and `SetVertexShader`, both replaced, and only the library's own
  `SetVertexShader` calls `Load`/`SelectVertexShader`. A later 5455 title that selects guest-made shaders needs this
  looked at.
- **Library code that still runs.** 30 D3D functions the game calls keep their console code (resource creation and
  locks, `SetVertexData2f/4f/Color`, visibility tests, callbacks, `SetRenderState_ZBias`, ...). They write NV2A
  methods into the push buffer, which the runtime walks; the immediate mode methods 5455 writes (0x1880 + reg * 8,
  0x1940 + reg * 4, 0x1A00 + reg * 16, 0x1518) are the ones `ApplyImmediate` handles. The internal DSOUND voice code
  writes APU registers (0xFE82xxxx) but is unreachable: every DSOUND entry the game calls is replaced.
- **`dsound.cpp` structures.** `DSBUFFERDESC` (+4 flags, +8 bytes, +0xC format, +0x10 mix bins), `DSMIXBINS`
  (count, pairs of {bin, volume}) and the 3D flag 0x10 read as 5455's `CDirectSoundVoiceSettings` reads them.
- **Effects image.** MOHRS embeds its image at `0x1F2F20` (`0x3360` bytes, passed to
  `IDirectSound_DownloadEffectsImage` at `0x15542C`) with one effect, the I3DL2 reverb, whose decrypted code hashes
  as the 5849 reverb `dsp_image.cpp` reproduces (`tools/dsp_image_check.py`).

No runtime source change was needed for MOHRS. Still open, to watch for at run time:

- The 58 oracle-only addresses are trusted on two counts (XbSymbolDatabase plus a matching convention); any that
  misbehaves is the first suspect.
- Display mode flags: MOHRS reads none, see the layout section.

## Tools

| Command | What |
|---|---|
| `xbe_symbols <xbe> sdk/xdk --library MOHRS.dll --out <toml> --candidates <txt>` | scan, plus candidates for the misses |
| `xbe_symbols --check config/game.toml sdk/xdk` | hand-filled addresses against the signatures |
| `python tools/symbols_compare.py config/game.toml re/xbsdb_default.txt [--apply]` | config against another symbol list |
| `python tools/lib_inventory.py <xbe> config/game.toml [list] [--all]` | library functions game code calls, named or not |
| `python tools/disasm.py <xbe> <va> [count] [--names ...]`, `--callers <va>` | disassembly, call sites |
| `python tools/hle_audit.py <xbe> config/game.toml [sdk/runtime]` | HLE declarations against the stack bytes the image pops |
| `python tools/dsp_image_check.py <xbe> <va> <size> [layout.toml]` | which effects of a DSP image the runtime reproduces |
| `re\xbsdb-build\projects\cli\XbSymbolDatabaseCLI.exe <xbe>` | the oracle (clone and build: see `HANDOVER.md`) |
